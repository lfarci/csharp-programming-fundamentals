---
name: add-exercise
description: Add, change or renumber an exercise in this repo (exercise page, solution, example tests, inventory). Use whenever exercises/, solutions/ or tools/generator data change.
---

Every exercise lives in one `ex(...)` call in `tools/generator/data*.py`. The pages are output.

0. **Prefer a drill.** Is the need "more practice of a pattern"? Add a `drill(...)` in `tools/generator/data7.py`, a near copy of an existing drill with only the target changed (by 3 → by 5, evens → odds). Skip the rest of step 3 and 5: `drill` writes the `ex`, `M` and `GOALS` entries. Never copy a *C# Player's Guide* challenge.
1. **Place it.** Pick the family letter, then the **group** in `tools/generator/themes.py` and the position in its `ids` list: after its `pre`, before any harder level (Guided, Independent, Challenge never go back inside a group). Prefer an existing group; a new group needs 2 or more exercises, a new theme 3 or more and its row in `tools/generator/learn.py`, or `gen.py` stops. Name the **one new difficulty** it adds. Choose `pre` so that everything else is already practised, at the same step or earlier. Done when you can say the new difficulty in one sentence and every `pre` exists.
2. **Number it.** Take the next free number in the family; renumbering an existing ID means updating every mention (`rg "\bX07\b"`) in ROADMAP, cookbook mini exercises, docs and other `pre` lists.
3. **Write the `ex(...)` call** in the data file of its family: `id, slug, title, level, stars, recipes, pre, goal, examples, edge, constraints, hints, mastery, code` (`paper=True` + `answer` for a paper exercise; optional `note`, `teacher`, `euler`). The title is at most 24 characters and does not repeat the kind (`Arrange:` / `Fix:` prefixes only). Follow the plain-language rules in `docs/writing-guide.md`: goal in one or two short sentences, hints from smallest nudge to near-solution, at least 2 for Guided, a mastery check that is a *new variation*.
4. **Make examples real tests.** 2–4 examples, including one edge case (0, 1, empty). Print results with `Console.WriteLine` on their own line so they match as line endings.
5. **Choose the shape and write the solution.** Computing one result (number, bool, text, array) or drawing → a *method exercise*: add `M[id]` in `data5.py` with the signature, the solution body, the starter `return`, 3–5 `cases` (one the starter's `return` fails), plus `GOALS[id]` in plain words (and `RULES`/`HINTS` overrides when the statement talks about reading or printing). A first contact with a recipe → consider a *Parsons* exercise; right after a write exercise → a *debug* exercise whose bugs are that recipe's common mistakes (put both in `data6.py`, see `task` and `NOTE_P` in AGENTS.md; check that the bugged starter compiles and fails). Input loops, menus, files → a *program exercise*: put the full `Run()` body in `code`. Beginner style, only what its step teaches, a hand-written loop.
6. **Regenerate and check.** The generator writes `tests/Practice.Tests/Exercises/<Class>Tests.cs`: open it and check that each test reads as a sentence (inputs and expected values visible, `DisplayName` in words). Run `python3 tools/generator/gen.py && tools/check-exercises.sh`, then try it as she would: `./ex start <ID>`, `./ex check` (expect NOT YET), paste the solution, `./ex check` (expect DONE), delete your practice file. Then `tools/verify.sh`. Done when every check is green.
7. **Link it in.** The website picks the exercise up from the regenerated `.vitepress/course.json` (its theme table and Previous/Next; never the sidebar); check it with `npm run docs:dev`. Add the ID to its `DRILLS` row in `data7.py`, at its course-order position (the generator fails on an unknown ID or a row out of order). Run `python3 tools/check-structure.py`. Check that the exercise trains one of its ROADMAP step's objectives (add or reword the objective if not). Add the ID to its ROADMAP step's **Exercises** line and, when it trains a recipe, to that recipe's Mini exercises.
