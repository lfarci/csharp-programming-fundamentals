# AGENTS.md

A C# loop **rescue course** for one true beginner (a university student, Programming Fundamentals, struggling with loops). Every page is read by her, so every change is judged by one question: *does this make the next step easier for a struggling beginner?*

Deeper reference, reached only when the branch fires:

- Who the learner is → [docs/learner-persona.md](docs/learner-persona.md). Read it before writing any learner page.
- Writing or reviewing learner text → [docs/writing-guide.md](docs/writing-guide.md) (teaching rules, the 6-step lesson format, exercise types, plain-language and accessibility rules, with sources).
- Adding or changing an exercise → skill [.agents/skills/add-exercise](.agents/skills/add-exercise/SKILL.md).
- Reviewing the repo → skill [.agents/skills/review-content](.agents/skills/review-content/SKILL.md).

## Map

- **Themes** are the units of the path: **4 themes** (Basics, Loops, Arrays text and lists, Methods and errors), labelled with their Microsoft Learn parts, each split into **groups** of same-pattern exercises (Loops has 9: Count, Add up, Keep only some, Until the user stops, Draw rows and grids, Draw shapes, Digits, Changing values, Search and combine). `tools/generator/themes.py` is the only place they are defined (slug, title, part, summary, objectives, groups with their recipe and **the ordered list of exercise IDs**, ready-when). **The groups are the course order**: theme tables, Previous/Next, `./ex next` and the drill sets follow them; `ex(...)` calls hold no theme. Always say *theme* and *group*, never *step* or *week*. `ROADMAP.md`, `themes/<slug>.md` (Learn card, objectives, group cards, one tick table per group), `exercises/README.md` (overview + drill sets), `docs/README.md` (study skills index), `docs/progress-checklist.md` and `diagrams/roadmap.d2` are **generated** by `tools/generator/pages.py`.
- `cookbook/`: 12 loop **recipes**, the decision diagram, `combining-recipes.md`, and the theory pages (`which-loop.md`, `the-maths.md`). Theory goes here, never in the roadmap.
- `learn/` (**generated** by `pages.py` from `tools/generator/learn.py`): the **Learn** section. This course is for practice; **the theory comes from Microsoft Learn only**: the 6 learning paths of *Get started with C#* (the Foundational C# with Microsoft certification on freeCodeCamp) and the video series *C# Fundamentals for Absolute Beginners*. `learn.py` holds the parts, their modules and the episodes as listed by the official Learn catalog and show APIs, and maps every theme to a main part, modules and episodes; it feeds the *Learn the theory* box on each theme page, the Learn pages, the roadmap labels and `course.json` (`mslearn`). `gen.py` stops if a theme, module or episode is missing. Only add a resource you opened (it returns 200); copy titles and links only, never Microsoft Learn text. The Learn section, in this order: **Overview** (`learn/README.md`, "How it fits together": `LearnFlow` shows theme, module, video, exercises per theme), **Microsoft Learn modules** (`learn/microsoft-learn.md`, the 6 parts as numbered cards), **Videos** (`learn/videos.md`, a `VideoGallery` of cards with the official thumbnails from the show API, `THUMBS`, hotlinked; `None` when the official image is missing, never an invented one) with **one page per kept episode** (`learn/videos/<slug>.md`: thumbnail linking to Microsoft Learn, our own short notes from `NOTES` with key words that must exist in the glossary, and Practise after this), **Certification** (`learn/certification.md`, facts only from the freeCodeCamp and Microsoft announcements in `CERT_SOURCES`; say "rules can change" rather than guess) and **Extra exercises** (`learn/quest-tracker.md`, with a real screenshot `docs/assets/quest-tracker.jpg`). **Video selection rule**: keep an episode only if it teaches a fundamentals idea that one of our themes practises (it appears in `THEORY`); every other episode goes in `DROPPED` with its reason (classes and OOP, namespaces and assemblies, LINQ, events, tooling, intros). `gen.py` stops if an episode is in neither list or a kept one is used by no theme. The C# Quest Tracker (<https://lfarci.github.io/csharp-quest-tracker/>) is the place for extra exercises.
- **Navigation order** (navbar, sidebar, home cards): Start here, Roadmap, Learn, Cookbook, Exercises, Study skills last. Prev/next links follow the sidebar.
- **No book content**: *The C# Player's Guide* is copyrighted. Never reference, map or summarise its content (chapters, levels, challenges); the only mention allowed is one neutral sentence on the Extra exercises page saying the Quest Tracker follows it, with a link to the official site.
- `diagrams/`: every diagram, as a D2 source (`x.d2`) and its committed SVG (`x.svg`), all sharing `_style.d2`. Pages embed the SVG as a Markdown image whose alt text is the full text version, so it works on GitHub and the site. Render with `tools/diagrams.sh`; no Mermaid.
- `exercises/`, `solutions/*.cs`, `tools/starters/`, `tools/exercises.json`, `tests/Practice.Tests/Exercises/*Tests.cs`, `docs/progress-checklist.md`: **generated**. Never hand-edit them.
- `tools/generator/`: the single source of truth for every exercise (`data1.py` → `data4.py` statements, chained imports; `data5.py` the method each exercise asks for; `data6.py` ladder, Parsons and debugging exercises; `data7.py` the drill bank and `DRILLS` (drill sets in `exercises/README.md`, each row in course order); `data8.py` search drills and the Methods and errors exercises; `themes.py` placement and order; `gen.py` renders, `pages.py` the theme pages).
- `docs/`: learner guides (getting started, reading an exercise, problem solving, practice, glossary) + the writing guide.
- `practice/`: **her** project. `./ex start` copies a starter here and never overwrites; nothing else writes here. `Program.cs` and `Practice.csproj` are plumbing she never edits (they run the current exercise via `tools/ex/Runner.cs`).
- `./ex` (`ex`, `ex.cmd` → `tools/ex`): start, check, run, next, list, progress, done. `./ex check` saves passed exercises in `practice/.done`; `./ex progress` writes `practice/PROGRESS.md` (both gitignored, inspired by [C# Quest Tracker](https://github.com/lfarci/csharp-quest-tracker)).
- `.vitepress/`: the website (VitePress, <https://lfarci.github.io/csharp-programming-fundamentals/>). It is built from the repo Markdown itself (`README.md` → folder index), so never copy a page into it. **The site home is `home.md`** (a VitePress home: what the course is, what is in it, how it works, where to go, the VS Code demo video), **separate from the root `README.md`**, which stays short and useful on GitHub (badges, quick start, link to the site). Repo-only things (Codespaces badge, GIF) stay out of `home.md`. Vue components in `.vitepress/theme/` (`RoadmapPath`, `ExercisesOverview`, `ThemeGroups`, `ThemeExercises` (one per group), `ExerciseHeader` (where you are, level, lesson, Mark as done), `LearnCard`, `DrillSets`, `CardList` (cookbook and study skills indexes), `ProgressPage`) show live progress; their GitHub fallback sits in a `<div class="gh-only">`, hidden on the site. `course.json` (sidebar, exercise header, Learn cards, drill sets, progress) is **generated** by `gen.py`. **The sidebar lists sections, themes and groups only, never one link per exercise**: exercises are reached from the group tables and from Previous/Next, which `gen.py` writes as page frontmatter (inside the theme, in course order; at the ends, the theme pages). `progress.md` is the one site-only page. Relative links to non-page files (`.cs`, tools, agent notes) become GitHub links at build time. Preview: `npm ci && npm run docs:dev`; build: `npm run docs:build` (fails on dead links). Progress lives in the browser (localStorage key `csharp-programming-fundamentals:progress:v1`); `./ex progress` prints a sync code (`CPF1:A1-4,7;L11`) that the site imports, format in `.vitepress/theme/sync-code.ts` and `SyncCode` in `tools/ex/Program.cs` (keep both in step, `tools/check-site-sync.ts` tests it). `site-tests/progress.spec.ts` (Playwright, `npm run test:site`; `SITE_URL=<live url>` to test the deployed site) ticks Mark as done, reloads, checks the counts and imports a sync code in a real browser.
- `tests/Practice.Tests`: xUnit v3. **One plain test file per exercise** (`Exercises/<Class>Tests.cs`, one `[Fact]` per example with literal inputs and expected values, `DisplayName` in words) plus the small shared helper `Expect.cs` (`Returns`, `Prints`, `Output`: friendly messages, 5 s time limit). A test file is compiled only when `practice/<Class>.cs` exists (MSBuild target `OnlyStartedExercises`), so exercises not started yet never break the build. `-p:ExerciseProject=` points the tests at `solutions/` in CI. Tests are also visible in Test Explorer (`CSharpFundamentals.sln`).

## Pedagogy (the rubric)

- **One new difficulty** per exercise: everything else in it is covered by its `pre` exercises. Levels fade the help: Guided → Independent → Challenge.
- **Read before write**: every new recipe gets predict → trace → complete (or arrange) before a blank file, and a debugging task that plants one of its common mistakes.
- **Drills over challenges**: to add practice, add a same-pattern **drill** (`drill()` in `tools/generator/data7.py`) that changes only the target, never a clever combined challenge. Add its ID to the right `DRILLS` row, in difficulty order. A recipe needs 5–12 drills.
- **Simple ideas**: goal in 1–2 short sentences; she will come back to it often. The examples table comes from `cases`, so it always matches the method. One new difficulty only.
- **Her files**: learners write only in `practice/` (`practice/*_*.cs` is gitignored). Never ship a file matching that pattern.
- **Objectives first**: every theme (in `themes.py`) starts with objectives using checkable verbs (trace, write, find the bug); its exercises must train exactly those.
- **No weeks**: no week numbers, dates, "you are here" or catch-up plans anywhere. The path is an order of themes, not a calendar.
- **Balance**: a theme has at least 3 exercises; a group 2 to 14. Too many in one place? Split it into groups. A tiny theme? Merge it into its neighbour.
- **Levels never go back inside a group**: Guided, then Independent, then Challenge. An easy drill added later goes *before* the harder exercises of its group, not after them (the old ID order put easy drills after Challenges).
- **No near-duplicate**: a new exercise must change one thing from its neighbour *and* add something; a repeat of a Parsons task as a blank file is fine, a second identical write task is not. A mastery check is a new variation, never the same task with another symbol or "do it again".
- **Order holds**: each `pre` sits earlier in the course order (`gen.py` stops otherwise) (one known exception: F01 waits for R01, because `File.ReadAllLines` returns an array), and every list (theme pages, README start, recap) lists an exercise only after its `pre`.
- **Hand-written loops**: no LINQ, no `Math.Pow`, no `Array.Reverse`/`string.Join`/`.Contains` shortcuts. Solutions use only what the exercise's theme and earlier themes have taught (the Files theme builds text with `+=`; `List<T>` waits for the Collections theme).
- **Hints** in `<details>`, smallest nudge first; Guided exercises carry at least 2. Every exercise has a **mastery check**: a *new variation* solved alone another day ("do it again" is not a variation).
- **Solutions separate**: exercise pages link to `solutions/` only at the bottom.
- **One home per meaning**: the session shape and coach questions live in `docs/how-to-practice.md`, check commands in this file; other pages link there.
- **Plain English**: short sentences, "you", common words, concrete numbers; **every new word goes to `docs/glossary.md`** (one row, alphabetical, plain definition, link to where it is taught); review the glossary whenever a page adds a term. Swap academic words for plain ones: *turn* (iteration), *start value* (initialization), *small job* (responsibility), *a sentence that stays true* (invariant). She knows basic Git (clone, pull, commit, push): use it without explaining it, and keep CI, generator and agent detail here and in `CONTRIBUTING.md`.
- **Theory = Microsoft Learn first**: every theme page points to its Microsoft Learn part, modules and episode; use Microsoft Learn's words for concepts (iteration statement, Boolean expression, method, parameter, return value), explained simply, with a glossary row.
- **Visual identity (the Roadmap is the reference)**: numbered circle, white card with a thin border and 12px radius, thin progress bar, one blue accent (`#3451b2`), no shadows except on hover. The shared classes live in `.vitepress/theme/custom.css` (`cpf-card`, `cpf-link`, `cpf-num`, `cpf-bar`, `cpf-kicker`, `cpf-button`); use them in every new component (overview, theme table, progress, Learn cards, Microsoft Learn path, home) instead of new styles. Logo and favicon: `public/logo.svg` (a loop arrow), with `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192/512.png` rendered from it.
- **Progress lives under Exercises**: the Exercises overview opens with the progress card; `/progress` (sync code import, backup) is linked from there and from the Exercises sidebar group, not from Start here.
- **One topic per page, short and visual**: a page answers one question. Lead with a picture, a table or a worked example, then a few short sentences. If a page grows a second topic, split it and link.
- **No emoji**: none in pages, headings, diagram labels, code, test names or `./ex` output. Status is a word: OK, NOT YET, DONE, FAIL. The verify step `No emoji` enforces it.
- **Accessible**: alt text on images, a full text version as the alt text of every diagram (and the same facts in the text nearby), meaning never in colour alone, descriptive link text, headings in order.
- **Navigation**: every page opens with a breadcrumb (`Home › …`) and ends with Previous/Next or Back links.

## Formats

**Exercise** (rendered by `gen.py`): frontmatter prev/next, breadcrumb `Home › Exercises › Theme › Group › ID`, `# ID · Title`, the `ExerciseHeader` card (theme › group, *Exercise N of M*, level, kind, lesson, do first, Mark as done; a table for GitHub), then Goal, Examples, Edge cases, Rules, Before coding, Hints, Mastery check, Solution, Previous/Next (GitHub only; the site shows the pager).

**Titles**: at most 24 characters, a plain name of the task ("Count by 3", "Digit sum"). The kind is a badge, so no "(paper)" and no "Fix the bugs:" prefix; Parsons and debug tasks start with `Arrange:` or `Fix:`.

**Learn the theory card** (`LearnCard`, data in `learn.py`): one **Watch** (the first episode of the theme), one **Read** (the first module), **Then practise** (the first exercise); everything else collapsed under *More on Microsoft Learn*. Put the most useful module and episode first in `THEORY`.

**IDs**: one family letter + two digits, ordered by difficulty. B basics, C conditions, L loop mechanics, A accumulators, G 2D drawings, D digits, S state, P search & primes, M combine, R arrays, T text, F files, E exceptions, K collections, N methods. Each exercise is placed by listing its ID in one group of `themes.py`; IDs and file names never change, so sync codes and tests stay valid. `paper=True` makes a paper exercise with an answer key in `solutions/ID.md`. `task="parsons"` (starter = the solution lines, shuffled and commented) and `task="debug"` (starter = compiling code with 1–2 planted bugs) use a starter string that begins with `NOTE_P` (`//! `), kept as is. Give each of them a `check_hint` (in `CHECK`, `tools/generator/data7.py`): `./ex check` shows it instead of the generic hints. A bridge exercise sits elsewhere than its family: just list it in that group (L09 opens *Draw rows and grids*, L19 opens *Add up*).

**Exercise shape**: one file, one `public static class ID_PascalName` in namespace `Practice`.

- *Method exercise* (entry in `data5.M`): she fills in the method(s); its parameters are the input, `return` the result. The page shows `GOALS` and a call → result table; the tests call the method by reflection with `cases`. Drawings are `void` methods whose printed text is compared. Add a case the `TODO` starter fails (CI checks this).
- *Program exercise* (no entry): input loops, menus, files. She writes `public static void Run()`; the tests feed the example input and match printed lines as *line endings* (prompts from `Console.Write` share the line), so results go on their own `WriteLine`.
- Methods are allowed from the first theme, framed as "input = parameters, result = return"; unit-test vocabulary stays behind `./ex check` until the Methods theme.

**Recipe** (`cookbook/NN-name.md`): breadcrumb, `# Recipe N · Name — tagline`, one-line quote, a "how this page works" line, then the 6 lesson steps of `docs/writing-guide.md#2-lesson-format`: 1 · Goal (one sentence), 2 · Predict (working example, answer in `<details>`), 3 · Trace it (table of the *same* example), 4 · The pattern (numbered **subgoal labels**, then Recognize it, The idea with diagram, Template as `###`), 5 · Complete it (blanks `____` or lines to arrange, answer in `<details>`), 6 · Your turn (linked IDs, then ### Debug it with one bug and the answer in `<details>`, then ### Common mistakes), Next.

**Diagram** (`diagrams/x.d2`): import the shared style (`...@_style`), use its classes (`step`, `ask` for questions, `end`, `note`, `part`), `direction: down` for decisions and `right` for sequences, short labels. Do not name a node `steps` (a D2 keyword). Run `tools/diagrams.sh`, commit the `.d2` and the `.svg`, embed the SVG with a full text alt.

## Checks

`tools/verify.sh` runs the same checks as CI (`.github/workflows/checks.yml`, one job per row below); all green before every merge.

| Check | Local | Gotcha |
| --- | --- | --- |
| Generator in sync | `python3 tools/generator/gen.py` then `git diff` | Edit data, regenerate, commit both. |
| Course structure | `python3 tools/check-structure.py` | Titles at most 24 characters and without the kind, every exercise in one group and linked from its theme page, levels never go back in a group, drill sets in course order, theme and group sizes, no exercise in the sidebar. |
| Exercises | `tools/check-exercises.sh` | One exercise builds alone with `-p:OnlyExercise=<Class>` (what `./ex check` uses). Every exercise has a test file; reference solutions pass every test (via `-p:ExerciseProject=solutions/Solutions.csproj`), every starter compiles and fails at least one example, `./ex` runs. Projects target net8.0 with `RollForward=Major`; `global.json` opts `dotnet test` into Microsoft.Testing.Platform (needed on .NET 10 SDK); `./ex` runs the test exe directly, so it works on any SDK. |
| ./ex end to end | `tools/check-ex.sh` (called by check-exercises) | Fresh copy of the repo: start, NOT YET, DONE, a broken other file does not block, progress, done, next. |
| Website | `npm ci && npm run docs:build && node tools/check-site-sync.ts` | Workflow `site.yml` builds on PRs, deploys to GitHub Pages on main. Dead links fail the build. Then `npm run test:site` (Playwright, Chromium) tests the ticks. |
| No emoji | `python3 tools/check-no-emoji.py` | Every tracked text file. Use words. |
| Diagrams | `tools/diagrams.sh --check` | Needs D2 v0.9.0 (the release tarball, as in `checks.yml`). Fails if an SVG is missing or differs from its source. |
| Markdown lint | `npx markdownlint-cli2` | Config `.markdownlint-cli2.jsonc`; a heading ending in `C#` trips MD020, so reword it. |
| Links | `python3 tools/check-links.py [--external]`, `lychee --config lychee.toml .` | doi.org and publishers answer 403 to bots: accepted. |
| Spelling | `npx cspell "**/*.md"` | British and US spellings both allowed; add real words to `cspell.json`. |

## Shipping

Branch, PR, wait for green checks (`gh pr checks --watch`), then merge. `main` is never force-pushed.
